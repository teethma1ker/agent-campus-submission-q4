# 02 方案设计

## 架构

```
CLI → cli.py（场景/故障注入/已有脚本） → agent.py（ReAct 循环 + 声明核对）
        ├─ gateway.py（真实 LLM / 离线决策器）
        └─ tools.py：search_materials / estimate_duration / check_rules / save_script
```

## 调用流程与动态决策

检索（主题 + 场景补充检索）→ 按素材事实写首稿（约目标 1.25×）→ 估算 → 超时则压缩重估（逐档：
删场景句 → 减产品事实 → 减分镜）→ 时长达标后规则检查（编造则删改重检）→ 保存（工具再复检）。

| 工具结果 | 下一步 |
|---|---|
| 检索无结果/不相关 | 改写关键词重试一次；仍无 → 说明无可用素材 |
| 估算超目标 | 压缩旁白后重新估算（最多 4 档） |
| 目标低于平台下限 | 明确说明无法满足并停止 |
| 目标远超素材可支撑时长 | 说明素材可支撑的最大时长，请补充素材 |
| 规则检查发现编造数字/属性 | 删除无依据表述后重新检查 |
| 保存失败 | 修正后重试一次 |

## 质量防线

- 时长只认 estimate_duration（按 4.5 字/秒逐分镜，最短 2 秒）；
- 事实追溯：脚本中每个数字、每个产品属性词（设计/外观/亮度/价格等）必须出现在所引用素材 facts 中；
- 保存工具内部复检估算与规则，任何一项不通过即拒绝保存；
- 声明核对：总结中的效果类百分比、总时长、保存声明与工具真值比对。

## 技术取舍

- 时长与规则在工具层而非提示词层，保证任何模型都无法绕过；
- 压缩采用确定性降级策略，可解释、可复现；
- 事实追溯采用“数字 + 属性词表”双层，覆盖最危险的两类编造。
